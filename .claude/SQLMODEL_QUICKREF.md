# SQLModel + Alembic Quick Reference (Meridia)

For @ezio and @primo. Meridia uses **SQLModel** exclusively — never SQLAlchemy
`declarative_base`. Money is stored as integer minor units (cents), never floats.

## Defining a table

```python
from datetime import UTC, datetime
from enum import Enum
from sqlmodel import Field, Relationship, SQLModel


class BoxOrderStatus(str, Enum):
    pending_payment = "pending_payment"
    paid = "paid"
    cancelled = "cancelled"


class BoxOrder(SQLModel, table=True):
    __tablename__ = "box_orders"

    id: int | None = Field(default=None, primary_key=True)
    client_id: int = Field(foreign_key="users.id", index=True)  # ownership key
    plan: str = Field(max_length=20)          # "single" | "subscription"
    price_cents: int                          # integer minor units, never float
    status: BoxOrderStatus = Field(default=BoxOrderStatus.pending_payment, index=True)
    pickup_slot: str = Field(max_length=20)   # "mattina" | "pomeriggio"
    created_at: datetime = Field(default_factory=lambda: datetime.now(UTC))
```

- `table=True` makes it a real table; omit it for a pure Pydantic schema.
- Add `index=True` to columns you filter/sort on (ownership keys, status, dates).
- Composite/unique constraints via `__table_args__ = (UniqueConstraint(...),)`.
- Register every model in `app/models/__init__.py` so Alembic autogenerate sees it.

## Separating table vs API schema

Keep the DB table (`table=True`) distinct from request/response DTOs in
`app/schemas/`. Never accept a raw table model as a request body — clients could
set `id`, `client_id`, `status`, etc.

```python
class BoxOrderCreate(SQLModel):        # request DTO (no table=True)
    plan: str
    pickup_slot: str


class BoxOrderRead(SQLModel):          # response DTO
    id: int
    plan: str
    price_cents: int
    status: BoxOrderStatus
```

## Querying with ownership isolation

```python
from sqlmodel import select

def list_my_orders(session: Session, client_id: int) -> list[BoxOrder]:
    stmt = select(BoxOrder).where(BoxOrder.client_id == client_id)  # ownership filter
    return list(session.exec(stmt).all())

def get_owned_order(session: Session, order_id: int, client_id: int) -> BoxOrder | None:
    stmt = select(BoxOrder).where(
        BoxOrder.id == order_id, BoxOrder.client_id == client_id
    )
    return session.exec(stmt).first()
```

Never `session.get(BoxOrder, order_id)` for a client-owned resource without also
checking ownership — that leaks another client's data (fails USER_DATA_ISOLATION).

## Alembic workflow

```bash
cd backend
# after adding/changing a model:
uv run alembic revision --autogenerate -m "add box_orders"
# review the generated file in alembic/versions/ (it is protected from auto-edit)
uv run alembic upgrade head        # apply
uv run alembic downgrade -1        # verify it reverses cleanly
uv run alembic history             # inspect
```

Rules:
- Always review autogenerated migrations — SQLModel type imports (`import
  sqlmodel`) must be present (the `script.py.mako` template adds it).
- Prefer additive, reversible migrations. Destructive ops (`drop_column`,
  `drop_table`, type changes) need a `# REVIEWED: expand-contract` note and a
  data-preservation plan (see the `MIGRATION_SAFE` rubric criterion).
- Backfills / data migrations are one-time artifacts — log them in
  `.claude/one-time-fixes/`.

## Common gotchas

- `session.exec(...)` (SQLModel) returns rows; `.first()` / `.all()` / `.one()`.
  Guard `.one()` — it raises if 0 or >1 rows. Prefer `.first()` + a None check.
- For raw SQL use `session.connection().execute(text("SELECT 1"))`.
- Datetimes: store timezone-aware UTC (`datetime.now(UTC)`).
- Enums stored as strings via `class X(str, Enum)`.
